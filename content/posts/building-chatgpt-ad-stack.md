对话式产品里的广告，需要先回答一个问题：用户现在是否已经形成了适合商业推荐的需求？一句关于产品的提问，可能是在比较购买选项，也可能只是假设讨论。多轮交流还会不断修改此前的条件。

OpenAI 在 2026 年 10 月 21 日发布的[广告技术栈文章](https://openai.com/zh-Hans-CN/index/building-chatgpt-ad-stack/)，介绍了如何用经过后训练的 LLM 编排广告流程。对 Agent 工程更有参考价值的，是它怎样分配决策权：模型理解语境，工具执行广告业务机制，客户端决定结果是否赶得上本轮展示。

## 会话状态要反映当前需求

原文用从跑步训练聊到跑鞋的例子说明，商业意图会随交流逐步出现。若每条消息都独立触发一遍广告流程，系统容易过早推荐，也会在条件变化时反复做无效计算。

ChatGPT 的做法是维护有状态的广告会话，在符合投放条件的轮次间更新信息。编排器需要识别指代、假设，以及已经过时的上下文；用户选择个性化广告时，还会利用可用的历史对话中的非敏感信息。

我的理解是，这里的状态管理需要保留“当前条件取代了什么”。例如，在一个假设的选鞋对话里，用户先问竞速鞋，随后明确只需要日常慢跑鞋。如果摘要只累加关键词，检索仍可能追逐先前的高性能需求。这个例子是整理者构造的，原文没有披露状态字段或更新算法。

因此，检验这类系统时，可以观察一次条件变更之后，后续查询是否跟着改变。历史信息保存得多，只回答了系统能记住多少；哪些信息仍然有效，需要另外验证。

## LLM 提名候选，竞价工具决定结果

编排器先把对话整理成一个或多个检索查询，再通过语义嵌入访问广告索引。多个查询能分别表达需求的不同方面，避免把复杂目标压进一个搜索字符串。候选经过资格过滤和质量评分，才有机会参与竞价。

这里有一个容易误读的分工：LLM 可以结合语境提名进入竞价的候选，但最终广告选择和价格由竞价工具执行。预算、投放节奏、质量调整后的排序等业务机制，也由相应系统处理。模型拥有语义判断能力，不代表它直接接管资金分配规则。

这给工具设计提供了一种可迁移的思路：允许 Agent 调整信息搜集和候选组织方式，同时把业务承诺留给有明确规则的接口。若一次推荐不合适，可以分别追查需求是否理解错了、候选是否召回不足，以及评分或竞价机制是否产生了不理想的结果。

原文还保留了竞价后的语境检查。一条广告本身合规、对话也允许展示广告，组合起来仍可能显得不妥，编排器可以阻止展示。这说明资格审核与语境判断承担不同工作；通过其中一项，不能替代另一项。

## 广告的时间预算由回答路径决定

广告服务与 ChatGPT 回答生成并行运行，使用独立的模型和代码。按原文描述，广告系统慢或不可用时，非广告回答继续生成，产品不会为等待广告而延后回复。

*图 1：原图，来源为 [OpenAI 原文](https://openai.com/zh-Hans-CN/index/building-chatgpt-ad-stack/)。两条路径分别生成非广告回答与赞助内容，广告结果不参与回答生成。*

服务端发出了广告，也还没有完成一次用户可见的展示。前端接收广告创意和模型生成的中立引言，只有它们在回答完全生成之前到达，并通过最终展示检查，才会在回复下方以赞助内容呈现。太晚到达，本轮就不展示。

我认为，这个设计给辅助 Agent 规定了很具体的运行条件：主任务继续推进，辅助结果必须在可用时间内产生价值。超时后放弃结果是预期行为，不能为了提高辅助流程的完成率，反过来拖慢主任务。

它也改变了优化目标。多一次工具调用可能改善候选质量，却也可能错过展示时机。单看检索准确率或广告服务平均耗时，都不足以衡量最终效果；还要观察多少合适的结果能及时到达。原文没有给出延迟分布、固定超时值或调用次数限制，这些只能在具体系统中测量和配置。

## “没有展示”需要进一步分类

原文把不返回广告视为正常结果，并记录流程中的细分状态：本轮不具备投放资格、会话启动但没有检索、检索为空、候选补全失败或未通过检查，以及交付后的用户互动。

这些分类对 Agent 的诊断很有用。若只记录“展示成功／没有展示”，主动放弃不合适机会与工具运行失败就会混在一起。前者可能是在遵守产品目标，后者才需要修复可靠性；两者需要不同的改进依据。

我的建议是，在设计类似流程时，为每个阶段记录决定及原因，再对照后续结果。比如，候选经常通过评分却在最后被判断为语境不合适，值得回看前面的评分信号；候选质量良好但总是来晚，则应先看调用耗时和调度。这里是根据原文机制提出的诊断方法，并非 OpenAI 已公布的实验结论。

## 模型反馈与人的反馈各有用途

OpenAI 还描述了用更强模型评判系统结果、据此训练负责具体任务的小模型的做法。这样，线上编排或检索可以使用效率更高的模型，质量改进则借助更强模型提供的反馈。

人的反馈包括点击、隐藏、调查和广告主反馈，用于校正产品方向与推荐分寸。对这种系统来说，判断“语义上相关”和判断“用户此刻愿意看到”有不同依据，模型评判需要与人的实际反应对照。

这篇文章提供了架构与职责划分，没有公布模型规格、完整训练方法或各模块的对照实验。它适合用来思考 Agent 怎样进入已有业务系统：哪些决定依赖语境理解，哪些必须交给业务工具，哪些辅助结果过时就该放弃。迁移到其他产品时，应先明确这三类决定，再选择模型和编排方式。
