这场 Stanford MS&E 435 访谈表面上谈 AI coding，真正回答的问题却是：当“把意图变成代码”越来越便宜，软件经济中什么会重新变得稀缺？Guillermo Rauch 的答案不是更多代码，而是把代码变成服务所需的一整条链路——可运行的部署、长时任务的状态与可观测性、安全沙箱、可组合接口、可靠运维，以及支撑计算的能源。

视频原题为 [Applications, Coding AI](https://www.youtube.com/watch?v=HA7lZd7zk3M)，嘉宾是 Vercel 创始人兼 CEO Guillermo Rauch，由 Stanford Online 于 2026 年 6 月 23 日发布，时长 49 分 22 秒，属于 Stanford MS&E 435 Week 8。以下内容依据人工英文字幕、时间戳来源记录和 22 页课程笔记整理。Rauch 同时也是基础设施供应商的创始人，因此本文把他的框架、Vercel 的公司自述和我的判断分开处理。

## 四个核心结论

1. 源码库只是中间态。软件部署后接触用户、产生错误与行为信号，产品学习才真正开始。
2. 云的基本对象正在从 Page 扩展到 Agent。任务运行数小时甚至全天后，状态、恢复、进度、成本和权限都会成为一等能力。
3. SaaS 更可能分层重组，而非整体消失。呈现层更容易按任务生成，权威记录、访问控制和业务工作流仍是可复用底座。
4. 智能体会偏好局部可理解、开放且可组合的“积木”。机器需求也会迫使平台把僵硬限额升级为带身份、预算和滥用防护的动态容量控制。

## 代码生成之后，部署才启动学习

Rauch 把编程史理解为访问权不断扩张的历史：个人计算、开源和云平台先后降低了获得工具与交付软件的门槛，编码智能体又把自然语言意图直接推向实现。每次抽象都没有消灭复杂性，只是把稀缺性推到下一层。[00:06:10–00:08:06](https://www.youtube.com/watch?v=HA7lZd7zk3M&t=370s)

这也是他强调“部署才让学习开始”的原因。仓库可以保存代码，却不会自动提供依赖、配置、密钥、网络、数据和持续运维。只有运行中的版本真正到达用户，团队才会得到行为、错误、转化或满意度信号，再用这些证据修改产品。AI coding 若只提高代码产量，却没有缩短“意图—运行—反馈”的闭环，价值仍停留在中间环节。

接下来，Rauch 用一个反事实命名说明云对象的变化：如果今天重新创建 AWS，它也许更像“Amazon Agent Services”。这不是 Amazon 的产品公告，而是一种思考工具。页面请求通常在毫秒级返回；智能体可能持续推理、调用工具、等待外部结果，并在数小时后交付研究、构建或维护任务。[00:08:27–00:10:29](https://www.youtube.com/watch?v=HA7lZd7zk3M&t=507s)

时间尺度一旦拉长，基础设施语义就会改变。按课程笔记的工程性归纳，长时任务需要可恢复会话、中间状态、检查点、异步通信、成本追踪与进度可观测性。运行越久，网络错误、限额变化、权限过期和依赖失效越可能发生。Agent cloud 的关键不是容忍一个更慢的请求，而是能够解释任务走到哪里、花了多少、为何失败，以及从哪里安全恢复。

## 智能体基础设施不是一个模型 API

Rauch 用一个三角形区分三组需求：给编码智能体运行其生成的软件；用基础设施构建面向客户或员工的智能体；让智能体参与配置、监控和优化基础设施。三者可以共享计算底座，却拥有不同的业务状态、权限模型和失败后果。[00:13:47–00:14:48](https://www.youtube.com/watch?v=HA7lZd7zk3M&t=827s)

这个区分让后面的产品清单变得有意义。AI Gateway 被类比为“token 的 CDN”，统一承接模型路由、观测、故障切换、安全策略和缓存；Sandbox 则既是智能体执行文件、进程与工具的“电脑”，也是限制网络、凭据和生命周期的风险边界。[00:17:54–00:21:02](https://www.youtube.com/watch?v=HA7lZd7zk3M&t=1074s) 网关不能因为两个请求语义相似就盲目复用高风险结果，沙箱也不等于安全已经完成。身份、上下文、权限、时效和副作用仍需单独验证。

“自驾驶云”则把智能体放进运维回路：观察日志、延迟和业务指标，提出变更或提交 PR，在受控环境部署，再根据技术与业务结果接受或回滚。[00:21:48–00:22:35](https://www.youtube.com/watch?v=HA7lZd7zk3M&t=1308s) 我认为这里最值得保留的不是自动化口号，而是闭环条件：建议、变更、独立验证与回滚缺一不可。一次部署成功不能证明优化成立，更不能自动授权智能体继续扩大影响范围。

## SaaS 不会整体消失，但呈现层会变得可塑

面对“vibe coding 会杀死 SaaS”的提问，Rauch 没有接受整体替代的叙事，而是把软件拆成不同层。传统 SaaS 必须用同一套界面服务大量客户，因而倾向最大公约数；生成式界面则能围绕组织、角色或一次任务重做呈现层。与此同时，数据库、权威记录、审批、权限和工作流仍可作为稳定底座。[00:24:07–00:28:29](https://www.youtube.com/watch?v=HA7lZd7zk3M&t=1447s)

两个案例说明了边界。停车管理故事只证明某个不满意的界面可以很快重做，没有覆盖迁移、安全、异常和长期维护；Vercel 销售团队的定制工作台则继续复用 Salesforce 的数据库与工作流。后者不是两个人重写 Salesforce，反而说明“可变界面 + 稳定记录系统”可能成为新的 SaaS 分工。

生成成本下降还催生了“一次性软件”。客户描述问题后，团队可以直接生成可运行演示，用一次会议验证理解，之后丢弃或继续迭代。它的价值不在长期留存，而在比幻灯片更高保真地传递需求。[00:29:09–00:30:30](https://www.youtube.com/watch?v=HA7lZd7zk3M&t=1749s) Rauch 所说的“software is basically now free”只适用于这类局部生成环节；模型调用、数据、部署、安全和维护并没有免费。

同一变化也会重写支持流程。客户智能体可能先选择并调用平台，失败后才把交互轨迹带给供应商。轨迹比人工复述保留更多路径和上下文，也可能包含密钥、个人数据与商业信息。把它转成 eval 之前，授权、脱敏、可复现性和最终责任必须先被定义。[00:31:01–00:32:09](https://www.youtube.com/watch?v=HA7lZd7zk3M&t=1861s)

## 局部推理决定谁能进入“积木经济”

智能体并不在空白世界里做技术选型。公开文档、开源代码、稳定 API 和训练或检索时的可见性，会让某些构件更容易被发现与调用。Rauch 借用 Mitchell Hashimoto 的说法，把这种竞争称为“积木经济”：与其为每个任务重建操作系统和网络栈，智能体更愿意复用便宜、稳定、可组合的现成能力。[00:14:48–00:17:09](https://www.youtube.com/watch?v=HA7lZd7zk3M&t=888s)

Tailwind 是他解释 local reasoning 的例子。长串样式类未必符合所有人的整洁偏好，却把理解和修改组件所需的信息收拢在局部，减少对远处全局样式的追踪。React、headless 组件和稳定 API 也沿着同一方向工作：上下文始终有限，边界越清楚，智能体越容易在较小预算内理解、搬运和组合能力。[00:33:27–00:36:39](https://www.youtube.com/watch?v=HA7lZd7zk3M&t=2007s) 局部性不能保证无缝迁移，但能减少必须同时加载的隐含依赖。

商业接口也会随之改变。Rauch 预测，智能体偏好原始信号和结构化数据、能够快速取得有限权限的入口，以及接近实际使用量的计费方式。[00:45:22–00:46:21](https://www.youtube.com/watch?v=HA7lZd7zk3M&t=2722s) 这不意味着绕过企业合规，而是把身份、授权、错误和预算变成机器可理解、可审计的控制面。

他随后提出“No more rate limits”，又立刻称其为一种 provocation。真正被批评的是把过去的人类调用频率固化成任意上限，而不是取消安全限流。面对并发智能体，平台需要动态容量，同时保留身份与 KYC、信用、账单上限、滥用检测、系统健康和租户公平。[00:46:21–00:48:05](https://www.youtube.com/watch?v=HA7lZd7zk3M&t=2781s)

## 我的判断：稀缺性迁移，不是工程消失

这场访谈最有价值的地方，是把“AI 会不会替代软件”改写成“软件各层的稀缺性如何迁移”。代码供给增加后，工程价值不会消失，而会更多落在三件事上：能否把意图闭合为可运行、可反馈的产品；能否让长时任务保持状态、证据和恢复能力；能否用最小权限的开放接口安全组合既有系统。

换句话说，软件的价值单位会从“产出多少行代码”，转向“在明确责任边界内完成多少可验证任务”。这不是开发者角色的终结，而是交付标准的上移。

这也给“软件免费”加上了必要限定。短命原型的边际生成成本可以迅速下降，生产系统的错误却会跨用户、跨数据持续传播。越靠近基础设施，验证、兼容、安全与回滚越不能交给生成速度代替。演讲中的工具选择比例、客户案例和增长数字也主要来自 Vercel 的展示，适合解释其战略判断，不足以证明市场份额或架构优越性。

Rauch 最后用“Energy goes in, intelligence goes out”把讨论拉回物理底座。[00:48:47–00:49:12](https://www.youtube.com/watch?v=HA7lZd7zk3M&t=2927s) 这不是线性公式，却提醒我们：能源、计算、模型、网关、沙箱、部署和治理共同构成价值链。代码越来越容易生成时，真正难的仍是把能力可靠、可控地送到用户手中。
