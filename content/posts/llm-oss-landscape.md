看到一个新的 AI 开源项目，首先需要判断它解决的是哪一层问题。[Agentic AI Landscape and Trends](https://github.com/antgroup/llm-oss-landscape)提供了一份代表项目索引，将 Agentic AI 生态分成 Agent Infra、Model Infra 和 Large Models 三层。

本文依据 2026 年 6 月 5 日保存的 README 整理，核对范围是项目对图谱的说明，没有逐一安装或评测其中工具。仓库持续维护，本文也不将这份历史快照当作当前排行榜。

## 三层分别描述什么

Agent Infra 包括应用、框架、运行时和工具生态，关注模型怎样被组织起来完成任务。Model Infra 覆盖数据、训练、模型服务和部署，关注模型怎样被构建并运行。Large Models 则描述为上层提供能力的模型基础。

这三层能帮助区分看起来都带有“Agent”标签的项目。例如，执行工具的运行时与承载模型推理的服务引擎，可能出现在同一个系统中，却承担不同职责。前者需要管理行动过程，后者需要处理推理请求，通常不能因为都属于基础设施就直接互换。

这一例子是对 README 分层的解释。图谱本身并没有为每个项目提供完整的调用链或依赖验证，不能仅凭所在位置推导它与其他项目已经兼容。

## 图中代表性与实际适用性有距离

README 明确表示，图谱选择具有代表性的项目，不追求覆盖全部生态。未入选项目可能只是超出当期收录范围，入选也不等于作者对每种使用方式作出推荐。

相应地，这份材料适合回答“有哪些方向和候选值得进一步查看”，不能直接回答“哪个最适合我的系统”。后者还需要目标任务、部署环境和现有依赖。项目热度可以提供调查线索，但不会自动说明接口契约、维护成本或产物质量。

旧项目增长较慢，也不能仅凭这一点认定它失去价值。不同层的项目有不同使用周期，横向比较之前需要先确认比较的是相同职责。

## 从地图继续走向项目材料

归档 README 除了三张分层图，还提供持续维护的 `data/agentic-ai-projects.csv`、动态洞察站点，以及提交遗漏项目的 issue 入口。这些入口让读者可以从概览继续定位资料，而不是停留在一张图片上。

一种使用顺序是先指出系统缺少的能力，再到相应层查找候选，随后阅读候选项目自己的说明、接口和限制。若要判断它是否适合替换已有组件，应进一步用实际任务检查输入、输出以及失败处理。这个顺序是本文整理的使用建议，不是图谱已经完成的产品评测。

这份仓库由 Ant Open Source 与 InclusionAI 发起，使用社区数据帮助观察生态变化，并接受社区补充。它的作用在于组织发现路径：先定位职责，再寻找材料，最后回到自己的任务验证。三层地图因此是一项调查的入口，不能替代调查结果。
