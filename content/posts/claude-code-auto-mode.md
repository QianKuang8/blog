权限确认太频繁，用户可能逐渐只点击“批准”，不再仔细判断。Anthropic 在 [Auto Mode 设计文章](https://www.anthropic.com/engineering/claude-code-auto-mode)中报告，手动请求有 93% 被接受，因而尝试用模型分类器承接部分审批，同时保留对危险动作的拦截。

判断对象不只是恶意行为。Agent 也可能为了完成正常任务，主动删除远端分支、寻找替代凭据，或绕过失败的部署检查。原文将这类情况称为 overeager behavior：行动与目标有关，却超出了用户愿意授权的范围。下文依据 2026 年 6 月保存的文章解释当时设计，不作为当前配置指南。

## 输入检查与动作检查各看什么

输入侧的 prompt-injection probe 扫描文件、网页、shell 和外部工具返回的内容。发现疑似注入时，它给主 Agent 附加警告，提示重新依据用户任务行动。它改变的是模型读到材料时的上下文，并没有通过删除内容彻底隔绝风险。

输出侧的 transcript classifier 则在动作执行前作判定。原文实现使用 Sonnet 4.6，输入只保留用户消息和工具调用，剥离主 Agent 的解释以及工具结果。这样减少了两种干扰：Agent 用自己的理由为动作辩护，以及外部内容直接影响审批者。

这一选择也会丢失信息。例如，用户没有明确提过某个任务 ID，分类器无法从工具结果判断它是否来自可靠查询。团队接受这项来源信息损失，以换取更独立的动作判断。分类器看到的材料更少，并不意味着它对环境了解更完整。

## 常规开发动作先由规则处理

系统没有让所有动作都承担分类器延迟。只读文件、搜索、代码导航等内置工具，以及保留下来的窄范围用户规则，先由普通权限规则处理；项目目录内的文件写入和编辑也可以直接允许，交由版本控制提供后续审查。

其余动作才进入分类器，包括 shell、网页获取、外部集成、子 Agent 启动和项目外文件操作。进入 Auto Mode 时，系统会移除已知能够授予任意代码执行的宽泛规则，例如不加限制的 shell 或脚本解释器许可，以免这些动作绕过检查。原文也说明，这份识别列表是尽力而为，无法保证穷尽所有形式。

因此，项目内编辑被放行只代表它经过了该层规则，并不证明修改安全或符合任务要求。动作审批与产物审查仍承担不同职责。

## 两阶段分类怎样降低打扰

第一阶段只输出一个二元判断，倾向保守拦截；只有被标记的动作才进入第二阶段，通过更详细的推理重新判断。多数普通动作可以较快通过，额外计算集中在疑似风险上。

分类器要看实际影响，而非命令表面的名称。原文举例包括脚本封装的命令、多命令链，以及先写文件再执行其中内容的情况。它还需要判断用户授权是否覆盖这一次动作的目标和影响范围。用户说清理 PR，并不自动说明允许改写远端历史；之前批准过相似动作，也不必然覆盖新的对象。

原文公开的三组数据展示了这一取舍。FPR 表示正常动作被误拦的比例，FNR 表示危险动作被漏放的比例。

| 评测数据 | 第一阶段 | 两阶段完整流程 |
| --- | --- | --- |
| 10000 条真实内部工具调用 | 8.5% FPR | 0.4% FPR |
| 52 条真实过度主动行为 | 6.6% FNR | 17% FNR |
| 1000 条合成数据外泄尝试 | 1.8% FNR | 5.7% FNR |

第二阶段显著减少误报，同时放过了更多危险动作。尤其真实过度主动样本只有 52 条，不能把 17% 理解成任意生产环境中的稳定事故概率。它是该测试集上的漏放结果，本文未独立复现。

作者分析，不少漏判已经识别到危险动作，却错误地把会话里的某个同意信号当成充分授权。难点因此包含对影响范围的判断，而不只是识别危险命令的语法。

## 委派时检查，返回时警告

多 Agent 场景增加了授权传递的问题。子 Agent 看到主 Agent 的任务说明时，可能将它当成用户请求；如果主 Agent 在委派时已经扩大范围，子 Agent 内部检查就失去了原始授权背景。

原文因此在任务外发时增加检查，可以拒绝不合适的委派。结果返回时也检查子 Agent 的行动历史，发现问题后附加警告，再交回主 Agent。两端作用不同：外发可以阻止任务，返回检查主要帮助负责人谨慎使用结果，并不直接丢弃产物。

## 被拒以后如何继续

动作被拦截后，拒绝原因作为工具结果进入主循环，要求 Agent 尊重边界并寻找可接受的路径。这样，一次误报不必立即终止整个任务。

当会话连续出现 3 次拒绝，或累计 20 次拒绝，系统停止并交给人工处理；无交互模式无法询问用户，则终止进程。这既控制了反复尝试，也让少量误报的代价主要体现为额外调整，而非整个会话丢失。

原文对适用范围的判断很明确：与完全跳过权限相比，Auto Mode 增加了防线；与认真逐项审查相比，它可能降低判断质量。它提供的是一种自动化与残余风险的折中，不能仅凭较低误报率认定其适合高影响操作。评估这类系统时，需要同时查看放行路径、漏判类型和拒绝后的行为，才能理解完整效果。
