机器之心这篇 [LLM 开源发展](https://mp.weixin.qq.com/s/D58GfDHogMS43Dl75fostw) 的信息量不小，但我觉得最值得抓住的不是“哪些项目上榜、哪些项目消失”，而是大模型开源生态正在从工具清单变成分层系统。

文章提到 2.0 全景图收录 114 个项目，较上一版减少 21 个，同时有 39 个新晋项目和 60 个项目出局。这个变化说明开源生态已经过了早期“什么都值得试一试”的阶段，进入更残酷的筛选期。

## AI Agent 层开始像云计算一样分层

文章最有价值的部分是对 AI Agent 层的观察。它说 2.0 全景图上的 AI Agent 已经从“百宝箱式工具堆”演化为类似云计算的分层体系。这个判断很重要，因为它意味着 Agent 生态不再只是单个应用，而是开始出现 infra、workflow、tool、framework 等生态位。

其中 AI Coding 增长曲线仍然陡峭，Agent Workflow Platform 沉淀为基础设施，Agent Tool 爆款频出，而部分 Agent Framework 下跌明显。我的理解是，早期大家会追框架，后来会更关心能否落到具体工作流、工具调用和交付链路里。

这和 coding agent 的发展一致。真正有粘性的，不一定是最通用的框架，而是能把模型、上下文、文件系统、工具、权限、验证和人类 review 串起来的完整工作环境。

## Infra 层更稳定，也更接近真实需求

文章把 AI Infra 的重点放在 Model Serving 和 LLMOps。模型服务继续升温，模型运维接棒 MLOps。相比应用层的快速变化，基础设施层的变化更像“静水深流”。

这很符合开源生态规律。上层应用会频繁换代，很多产品会被模型能力直接吞掉；底层服务、推理、部署、监控、评估、数据管道则更容易长期存在，因为它们承载的是重复需求。

## 开源正在从理想主义变成商业博弈

文章也提到“逐渐变味的开源”。这点不意外。大模型生态里的开源常常混合了研究传播、开发者生态、商业入口和竞争策略。模型权重、训练代码、推理框架、协议标准、应用项目的开放程度都不一样。

所以看 LLM 开源生态，不能只看 stars，也不能只看 license。更重要的是看项目是否有持续维护、是否有真实集成场景、是否处在稳定生态位上。

## 我的判断：开源生态的主线会从“项目热度”转向“系统位置”

这篇文章适合当作一次生态快照，但它真正提醒我的是：以后看 AI 开源项目，要问它在系统里占什么位置。

是模型层、推理层、数据层、Agent workflow、工具协议、评估平台，还是面向终端用户的应用？它的上游依赖是否稳定？下游是否有真实用户？模型能力升级会增强它，还是替代它？

如果只看名单，很容易追热点；如果看生态位，才更容易判断哪些项目会留下。
